## 分层云换装顺序图路径修复

用户在内置示例页遇到“顺序图生成失败，请重试”，且一次修正后页面持续停在“加编号中…”。本次按纯 bug 修复例外直接定位、补回归测试并修正实现，没有改变已确认的产品流程。

根因：

- 微信开发者工具日志显示，Canvas 2D 把包根路径 `/assets/samples/head1.jpg` 解析成了 `pages/dressup/assets/samples/head1.jpg`，因此第一张头像素材即触发 `ENOENT`；
- 直接复用相册保存前的“复制到 USER_DATA_PATH”逻辑会在开发者工具读取包内源文件时持续等待，页面因此卡在“加编号中…”；
- `wx.getImageInfo` 还可能把一个可读的页面相对路径重新归一化为 Canvas 无法正确解析的根路径。

修复：

- 分层换装新增顺序图专用路径解析，包内素材由 `/assets/...` 转为当前页面可读的 `../../assets/...`；
- 云文件、网络图片和用户本地图片继续走原有下载/本地解析逻辑；
- 顺序图合成器支持调用方注入路径解析器，并让 Canvas 始终使用解析器返回的已验证路径；
- 新增回归用例覆盖“图片信息接口返回错误归一化路径时，Canvas 仍使用页面相对路径”。

验证记录：

- 聚焦测试先出现 2 个预期失败，实施后 15/15 通过；
- 微信开发者工具重新普通编译后进入内置示例，12 张素材均完成编号，底部由“加编号中…”恢复为“微信预览 / 保存可用部位组”；
- 最新开发者工具日志未再出现 `pages/dressup/assets/...` 的 `ENOENT`；
- 点击“保存可用部位组”后发现并复现第二层故障：Canvas 已成功返回 `http://tmp/...jpg`，但 manifest 协议白名单误把微信开发者工具本地虚拟文件地址当作普通 HTTP 拒绝；
- 协议校验现只放行精确 `http://tmp` 主机，`http://tmp.evil.example` 与普通 HTTP 地址仍拒绝；
- 修复后重新普通编译，点击“保存可用部位组”已进入系统保存面板，控制台不再出现“导出图片路径协议不支持”；
- `npm test`：257/257 通过；
- `npm run check:syntax`：48 个首方 JS 文件通过；
- `npm run check:miniprogram`、`npm run lint`、`npm run check:docs`：通过。

README 无需因本次 bug 修复再次更新：功能名称、入口、用户流程和外部使用说明均未改变，仅修正内置素材进入 Canvas 的运行时路径。
