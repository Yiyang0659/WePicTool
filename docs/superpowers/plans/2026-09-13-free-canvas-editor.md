# 保存一致性与自由创作实施计划

依据：已确认的2026-09-13-free-canvas-editor设计。仅当前功能分支实施；线上版本、默认流量及审核策略不变。

## A：保存一致性（优先门禁）

- server.js：每次最终生成分配服务器生成的独立revision，不依赖可复用traceId或客户端值。
- renderer.js：保留版本化上传路径及本次失败回滚，测试相同项目重复生成不覆盖。
- tests：模拟缓存按文件地址复用，先原图再添加装饰与双色笔迹；验证提交快照、真实PNG像素差异和manifest使用新URL。禁止把响应200视为内容正确。
- 编辑页保存测试：确认修改触发重新生成、未修改复用、当前页/整组/预览指向一致的最新成品。
- 自动化通过后需新候选部署和同项目真机两次保存对照，未完成前不宣称线上缺陷已修复。

## B：自由创作（A通过后）

- funTextProject.js及场景校验：空白卡、独立文字对象、背景纯色，保留历史撤销和3–8张限制。
- 前后端场景绘制：支持相同模型，校验空正文和手绘审核，保持容量边界；新增能力在兼容服务器可用前不可对普通用户启用。
- fun-text-editor页面：空白卡入口，内容内文字选择与编辑，样式内背景颜色，装饰内明确手写目标与添加/更新按钮。
- 回归场景：原卡不覆盖、手写添加不替换、目标卡绑定、删除撤销、换样式不丢对象、保存后与预览一致。

## 检查与交接

### 015真机测试准备（用户确认继续）

为完成A的真机门禁，配置仅develop开发版生效的015测试参数；正式版、体验版、未知版本或API异常不加参数。共享客户端仅在/render-stack追加固定白名单参数，不改变身份校验、审核、重试或云端默认路由。补环境隔离测试，编译并生成开发预览码供用户扫码；不上传正式版本、不提交审核。真机相册操作需用户执行，不能以开发者工具成功替代。测试结束清空配置即可恢复开发版默认路由。

每阶段运行npm test、check:syntax、check:miniprogram、lint、check:docs及git diff --check。更新current和当日迭代；真机视觉与相册由用户完成。无新服务、收费开关、VPC或微信配置修改，无clearQuota、正式发布或全量切流。
