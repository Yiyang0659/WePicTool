# 保存发送、AI 自动归组与大图浏览

日期：2026-09-13
状态：用户已确认（2026-09-13），进入本地实施；云端部署另行授权。

## 现状证据

- outfit-import.showReviewTask 进入 review，onApplyImport 才 emitAndReturn；当前确实存在独立确认步骤。
- processOutfit 的 CLASSIFICATION_PROMPT 不包含 head，头像归 unsupported；前端四组不等于服务端已识别四组。
- MATTING_PROMPT 只要求去背景、保留主体；缺少分部位排除人体/其他服装和标准构图要求。当前已调用图像编辑模型，不是只做分类。
- 编辑主预览绑定 onPreviewTap，装饰及手写已有独立拖动事件，需要隔离新滑动手势。
- sequenceBadgeComposer 为共享角标出口，当前深色填充 rgba(18,18,20,.78)、白字 middle 基线加1像素。

## 1. 保存后去微信发送

穿搭、趣味字画及其预览保存成功后统一增加“去微信发送”按钮。保存过程中不可提前离开；部分失败优先继续保存，不宣称整组成功。

按钮说明“返回微信后，进入聊天，从相册按编号选择图片发送”。点击时保存草稿并调用 exitMiniProgram；该 API 仅退出当前小程序，不保证进入指定聊天、不自动带入整组图片或发送。不支持或失败时显示手动返回引导，不伪报成功。不引入聊天工具权限或新服务。

依据：微信官方 api-typings 中 exitMiniProgram 定义为退出当前小程序；showShareImageMenu 不作为本次整组发送实现。

## 2. AI 完成直接进入工作台

- 删除用户流程中的独立 review 页状态；处理完成后幂等追加本批结果并返回工作台，取消不提交。
- 从“用我的图片”开始保持空工作台；不自动补系统素材。已有用户/手动加入素材不清空；从试玩示例进入 AI 时先明确允许移除示例，不能静默删除。
- 四组顺序：头像/发型、上衣、下装、鞋子；没有本批素材且无已有素材的组保持为空。
- 末尾新增“其他素材”组：明确非四类的风景、美食等保留原图，不做服装重建；低置信度/处理失败另标“待确认”，不当成成功商品图。分类修正、删除、原图对比移到工作台素材操作里。
- 其他素材复用排序、编号和导出；不计入四部位完成数。沿用现有每组上限及不足3张提示，不暗中改变成叠门槛；超额保留待整理，不丢图。
- 新增 head 分类及完整适配；头像保留头部/头发，不使用去人体的服装提示词。

## 3. 衣物标准化

先修改现有模型的分部位图像编辑提示词：只保留目标服装、移除人脸/皮肤/手臂/腿/首饰/衣架/其他服装；保留颜色、图案、材质、领口和袖口，完整居中呈现，纯白背景。

后处理统一画布与主体边界，默认参考3:4商品图构图；主体限制边占画布约92%，等比适配、不拉伸、不裁袖口/鞋尖，预留编号位置。若保留用户比例选项，则各比例内使用同一占比规则。尺寸不靠提示词单独保证。用户确认侧拍/遮挡尽量按上传图大致样式还原，不保证不可见细节准确；“填满”指主体尽量撑满图片区域，不是拉伸到手机屏幕长宽比。

侧拍或被遮挡部分无法保证准确还原：允许合理商品化重建但必须提示AI可能改变细节；严重遮挡/模糊需换图，处理失败保留原图并标失败。不能把接口成功当作去人效果合格。先用用户样例及侧拍/白衣/鞋子验证，再决定是否需要额外质量模型；未经确认不开新付费服务、不无限重试、不部署。

## 4. 趣味字画浏览

主画布点击打开黑底全屏预览；左右滑动按当前 scene 顺序切换，同步序号/缩略选中，约250ms平移动画。文字编辑只由“改文字”进入。滑动不排序；装饰/手写对象命中时优先编辑手势，非对象区域横滑翻页；滑动结束不误触大图。

大图展示本地合成的完整文本/背景/装饰/手写；不审核。未审核图使用不带原生长按保存菜单的自定义查看器，禁止借预览绕过已有保存审核。关闭回到当前浏览卡，返回手势先关大图；失败不展示旧图冒充当前卡。

## 5. 编号

共享角标拟改为中灰 #8A8A8A，保留胶囊尺寸/位置和白字，弱化阴影；按文字度量校正视觉居中。更新角标版本使新导出重绘；旧相册图不被修改。覆盖穿搭、其他素材、趣味字画和预览物化输出。

## 验证及实施顺序

确认后写逐文件实施计划：浏览/角标/发送引导 → AI直回与其他组 → 图像处理与样图验收。回归保存门禁、手写拖动、卡片排序、重复提交、取消、失败续存、旧草稿、空组、其他组及原图恢复。

代码阶段运行治理全部检查，记录开发者工具与双端真机证据；真实AI样图质量和微信返回位置不能用mock替代。云函数更改仅本地，部署须单独授权。本设计不意味着可正式上线。
