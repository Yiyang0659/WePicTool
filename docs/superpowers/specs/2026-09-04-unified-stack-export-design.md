# 统一叠图导出与顺序识别设计说明

**日期：** 2026-09-04
**状态：** 用户已确认；分支实现与自动化完成，待双端和真实微信验收

## 1. 设计结论

统一穿搭叠图、分层云换装和趣味字画的最终导出契约。每一叠在进入微信预览和保存前，都先生成一组已经写入可见顺序角标的最终图片；预览、单张保存、按叠保存和断点续存只能消费这同一组图片，不允许各自重新推导顺序。

微信 `wx.saveImageToPhotosAlbum` 只接收本地 `filePath`，没有目标文件名或系统相册排序参数。因此本项目不再把“01、02 文件名控制微信顺序”写成可保证的产品能力。顺序采用三层保障：

1. 最终图片右上角写入 `01`、`02`……可见角标；
2. 小程序按清单顺序逐张保存，尽量让系统“最近项目”保持相邻；
3. 发送引导要求用户按图片角标依次勾选，并明确第 `01` 张是微信封面。

系统相册的实际排列方式和微信选择器的初始顺序只能通过 iOS、Android 真机验证，不能由自动化测试或文件名推断。

## 2. 背景与当前问题

项目的核心价值是让用户控制微信合并展示的封面和滑动顺序。当前三条链路已经能够顺序保存，但仍有以下缺口：

- 穿搭结果页显示 `numLabel`，角标没有进入最终图片；
- 分层云换装保存原素材，图片中没有组内序号；
- 趣味字画最终 PNG 有固定场景内容，但没有统一导出角标；
- 预览页、结果页和保存队列分别接收数组，缺少一份可校验的“导出清单”；
- 保存失败虽然已有 `nextIndex`，但不同页面对重试游标、顺序变化和缓存失效的处理不完全一致；
- 现有文档把编号文件名写成顺序保证，但微信保存接口没有文件命名能力。

如果继续增加玩法，每个页面都会再次实现编号、保存和续存，顺序问题会被复制。

## 3. 目标与非目标

### 3.1 目标

- 三种已实现玩法使用同一种叠图导出清单和连续序号规则；
- 预览内容与最终保存图片完全一致，用户在预览中看到的 `01` 就是保存后的封面候选；
- 单叠序号从 `01` 开始连续递增；多叠分别重新从 `01` 开始；
- 序号角标在白色、浅色、深色和照片背景上均可辨认，不遮挡主体；
- 批量保存失败后从失败项继续，不重复保存已经成功的图片；
- 任何卡片内容、数量或顺序变化都会生成新的导出指纹并清空旧续存游标；
- iOS、Android 和真实微信聊天形成可重复记录的验收矩阵。

### 3.2 非目标

- 不承诺修改系统相册文件名或强制系统相册排序；
- 不尝试自动勾选微信图片、直接发送到聊天或读取用户在微信中的勾选结果；
- 本次不实现回流引导卡、埋点、穿搭结果删除/排序、素材包扩充或趣味字画视觉改版；
- 不改变各玩法的卡片内容、叙事策略、分组规则和至少 3 张的发送门槛；
- 不在图片上增加品牌水印；顺序角标仅承担操作和反馈用途。

## 4. 用户体验

### 4.1 最终图片角标

每张可进入一叠的图片右上角显示两位数字：

- `01` 为微信封面候选；
- `02` 起表示后续滑动顺序；
- 1–9 也始终补零，超过 99 张不允许进入单叠；
- 角标使用半透明深色胶囊、白色数字和轻微投影；安全边距按图片短边计算；
- 角标视觉尺寸按图片短边的比例计算，并设置最小/最大像素范围；
- 不额外写玩法名、品牌名或“第 N 张”等文字。

角标位置本期固定为右上角。允许各玩法通过安全区参数把角标向内偏移，但不开放给用户自由拖动。

### 4.2 多叠规则

- 穿搭叠图：上衣、下装、鞋子各自为一叠，各组独立 `01…N`；“其他素材”不参与叠图编号；
- 分层云换装：头像/发型、上衣、下装、鞋子各自为一叠，各组独立 `01…N`；少于 3 张的组仍可预览，但不允许按叠导出；
- 趣味字画：选中的完整故事为一叠，按场景顺序编号 `01…N`。

“保存全部”按产品定义的叠顺序执行：穿搭为上衣 → 下装 → 鞋子；分层云换装为头像/发型 → 上衣 → 下装 → 鞋子；趣味字画只有一叠。组与组之间序号会重新从 `01` 开始，发送引导要求一次只发送一组。

### 4.3 保存与失败续存

保存前页面展示：

- 当前叠名称；
- 总张数；
- `01` 封面缩略图；
- “请在微信中按角标 01、02、03…依次勾选”的固定说明。

保存过程中展示“正在保存 N / Total”。某张失败时：

- 已成功保存的图片不回滚、不重复保存；
- 页面明确显示失败的角标，例如“`03` 保存失败”；
- 主按钮变为“从 03 继续保存”；
- 用户修改卡片、调整顺序或切换比例后，旧游标作废，从新的 `01` 开始保存。

### 4.4 发送引导

保存完成后的四步固定为：

1. 回到要发送的微信聊天；
2. 每次只发送当前这一叠，并按图片上的 `01、02、03…` 依次勾选；
3. 勾选微信的“发送后合并展示”；
4. 发送前确认 `01` 位于选择列表第一位。

不得出现“系统已经替你排好微信顺序”“文件名保证顺序”或“一键直发”的承诺。

## 5. 数据与接口设计

### 5.1 统一导出清单

新增纯数据契约 `StackExportManifest`：

```js
{
  version: 1,
  playId: 'layered-dressup',
  projectId: 'project_xxx',
  fingerprint: 'sha256-or-stable-hash',
  stacks: [
    {
      stackId: 'tops',
      title: '上衣',
      minCards: 3,
      cards: [
        {
          cardId: 'top_1',
          sequence: 1,
          sequenceLabel: '01',
          isCover: true,
          sourceUrl: 'cloud://... or local path',
          exportUrl: 'wxfile://...numbered image',
          width: 1080,
          height: 1350
        }
      ]
    }
  ]
}
```

约束：

- `stackId` 在单个 manifest 内唯一；
- `cardId` 在所属叠内唯一；
- `sequence` 必须从 1 连续递增，数组顺序必须与其一致；
- 只有 `sequence === 1` 的卡是 `isCover`；
- `sequenceLabel` 由共享模块生成，调用方不能自行传入；
- `exportUrl` 生成前为空，生成成功后必须是受支持的本地永久/临时路径；
- `fingerprint` 覆盖玩法、项目版本、叠顺序、卡片身份、源图身份、比例和角标样式版本。

### 5.2 模块职责

计划新增或收敛为以下职责；具体文件清单在设计确认后的实施计划中确定：

- `stackExportManifest`：从各玩法的项目数据构造并严格校验 manifest；
- `sequenceBadgeComposer`：接收已解析的本地图片和可复用 Canvas，输出写入角标的本地图片；
- `imageExporter`：只负责解析路径、按 manifest 顺序保存、返回游标和错误，不再推导业务分组；
- 结果页适配器：把 outfit、layered-dressup、funtext 数据转换为统一 manifest；
- `pages/preview`：优先接收 manifest，旧 `groups`/`task` 输入保留一版兼容，但统一转换后再渲染。

### 5.3 最终图生成与缓存

角标合成在小程序本地完成：

1. 将 `sourceUrl` 解析为本地路径；
2. 获取原图真实宽高；
3. 以原尺寸绘制图片和序号胶囊；
4. 导出与源图一致的可用格式；透明 PNG 继续使用 PNG，其余允许使用高质量 JPEG；
5. 将 `exportUrl` 与 manifest 指纹关联缓存。

同一指纹重复进入预览或保存时复用已生成图片。指纹变化时丢弃逻辑缓存；临时文件由微信生命周期管理，本次不增加长期图片副本。

为避免大图内存峰值，角标图片严格串行生成；单张失败阻断当前叠的保存，并保留已生成缓存供重试使用。

## 6. 各玩法适配

### 6.1 穿搭叠图

- 以结果页当前分组和当前比例为事实来源；
- 只有 `tops`、`bottoms`、`shoes` 生成叠；
- 每次改分类或改比例后重建 manifest；
- 当前页面上的 CSS 数字角标改为展示最终图本身的角标，避免双重编号；
- 单图保存仍允许，但保存的是带该组序号的最终图。

### 6.2 分层云换装

- 使用项目中四组的当前顺序构造 manifest；
- 内置素材和用户素材使用相同角标合成路径；
- 删除、左右移动、加入素材后重建 manifest；
- 不足 3 张的组可以生成编号预览，但保存按钮继续禁用。

### 6.3 趣味字画

- 使用选中候选的 `editedScenes` 和最终渲染结果构造单叠 manifest；
- 角标不进入场景 JSON，不影响预览/高清渲染一致性的业务指纹；它作为导出装饰层由统一导出模块添加；
- 改文字、换视觉包、调整顺序或重新渲染后重建导出指纹；
- 内容安全错误不得触发本地角标合成或保存降级。

## 7. 兼容、降级与异常

- 旧本地记录没有 manifest：打开后从项目快照或任务分组重新构造；无法确认卡片身份时允许查看，但保存前必须重新生成最终图；
- 卡片 URL 为空、协议不支持、图片解码失败或角标合成失败：当前叠不可保存，显示明确重试入口；
- 角标合成不允许在内容安全失败时作为“本地导出”绕过远端门禁；
- 页面销毁后异步完成的旧任务不得覆盖新 manifest；
- 连续快速点击保存只允许一个活动队列；
- 用户拒绝相册权限时保留当前 manifest 和游标，引导设置后从原位置继续；
- 低版本或不支持所需 Canvas 能力的设备保持原图预览，但禁用按叠保存并提示当前设备版本不支持生成顺序图，不静默保存无角标图片。

## 8. 测试与验收

### 8.1 自动化测试

- 三种玩法到 manifest 的映射；
- 多叠分别从 `01` 开始、连续序号和唯一封面；
- 空叠、重复 ID、越界序号、超过 99 张和不支持 URL 拒绝；
- 指纹对卡片内容、比例、数量和顺序变化敏感；
- 角标位置、尺寸、补零和深浅背景可读性绘制契约；
- 透明 PNG 与 JPEG 输出格式；
- 串行合成和串行保存；
- 第 N 张失败返回 `nextIndex=N-1`，重试不重复前 N-1 张；
- manifest 变化清空游标；
- 内容安全错误、过期异步结果和重复点击均 fail closed；
- 旧任务/记录兼容转换；
- 预览和保存消费相同 `exportUrl`。

### 8.2 视觉检查

至少覆盖：

- 1:1、4:5、3:4、横图和竖图；
- 白底白衣、浅色趣味字画、黑板风格和复杂照片背景；
- `01`、`09`、`10`、`99`；
- iPhone 小屏和 Android 常见屏宽下的预览缩放；
- 角标不遮挡趣味字画主文字、不覆盖穿搭主体关键区域。

### 8.3 真机与真实微信矩阵

每个平台至少验证穿搭、分层云换装、趣味字画各一叠：

| 项目 | 微信开发者工具 | iOS | Android | 真实微信聊天 |
| --- | --- | --- | --- | --- |
| 预览与最终图角标一致 | 必测 | 必测 | 必测 | 查看收到图片 |
| 逐张保存顺序 | 记录结果 | 记录相册表现 | 记录相册表现 | 不作自动保证 |
| 按角标选择后的封面 | 不适用 | 必测 | 必测 | 必测 |
| 左右滑动顺序 | 模拟页 | 必测 | 必测 | 必测 |
| 展开/收起顺序 | 模拟页 | 必测 | 必测 | 必测 |
| 中途拒绝/失败后续存 | 模拟错误 | 必测 | 必测 | 不适用 |

未实际执行的格子必须记录“未验证”，不能用自动化测试代替。

## 9. 发布与回滚

- manifest 契约使用版本号；新页面先兼容旧输入，完成所有调用方迁移后再移除旧契约；
- 顺序角标样式带内部版本号，版本变化会使缓存失效；
- 若真机发现角标合成造成崩溃或图片质量明显下降，通过功能开关禁用新的按叠保存入口，保留查看和旧记录，不自动退回无角标保存；
- 回滚不能删除用户本地记录；旧记录在旧代码中仍按原路径打开；
- 合并前必须完成完整自动化检查、`git diff --check` 和三条玩法的双端真机矩阵。
