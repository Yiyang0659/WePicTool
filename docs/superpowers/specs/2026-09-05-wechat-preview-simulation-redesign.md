# 微信效果预览页仿真改版设计说明

**日期：** 2026-09-05
**状态：** 用户已确认；已按两段真实微信录屏复核滑动及展开/收起并完成分支实现，待双端真机验收
**范围：** 微信小程序 `pages/preview/preview`

## 1. 目标

把当前“分享给好友”页面改成一个接近真实微信聊天的效果预演页，让用户在保存前理解四个部位组发送到微信后的折叠、滑动、展开和查看状态，同时始终明确这只是预览，不能伪装成已进入微信或能够直接把图片组转发给好友。

页面必须始终占满并锁定在当前设备视口内：系统区、会话导航和底部预览输入栏构成不随内容移动的微信外壳，只有中间聊天消息区能够上下滚动。图片消息按真机微信叠图参考收敛为约 `38vw` 的紧凑缩略卡；穿搭叠图使用接近 `3:4` 的预览框，图片居中填充，点击后仍通过大图查看完整原图。

本次只改预览页面的信息层级、视觉壳层和交互状态，不改变导出 manifest、编号图、组内顺序或相册保存规则。

## 2. 当前问题

用户截图和当前实现暴露出以下问题：

1. 页面硬编码了一个 `12:00` 状态栏，但真机已经存在系统状态栏，造成时间与图标重复；
2. 标题“分享给好友”更像操作按钮，不像真实微信会话中的联系人名称；
3. 背景纯白，导航和输入栏也全白，与微信浅色聊天页的灰色会话背景不一致；
4. “展开 3”固定在消息行左侧 24px，远离牌堆，形成四个悬空按钮；
5. 深灰色展开胶囊视觉过重，抢过图片本身；
6. 组名悬浮在头像上方，不属于真实微信消息结构；
7. 四组每组固定 164px 且留白较多，小屏需要长距离滚动；
8. 假输入框、表情和加号看起来可操作，但实际上没有输入能力；
9. 长按菜单中的“转发”只能分享小程序，不能转发生成的图片组，行为与文案不一致；
10. 缺少加载、图片失败、保存完成和返回编辑等状态的统一反馈；
11. 当前 `54vw` 且最大高度 `150px` 的稳定舞台会把 4:5、3:4 等竖图压得过矮，图片消息与真实微信的视觉占比不一致；
12. 页面根节点、聊天区和安全区高度没有形成唯一的视口约束，真机向下滑动时可能连导航、输入栏和整个页面外壳一起移动。

## 3. 设计原则

### 3.1 系统壳层只画一次

使用真机提供的系统状态栏和右上角小程序胶囊，不再绘制第二套时间、网络和电量。自定义导航只负责返回与会话标题，并根据 `statusBarHeight`、安全区和胶囊位置计算高度。

### 3.2 聊天内容高仿真，产品能力保持诚实

消息背景、右侧头像、图片牌堆、展开后的独立消息行和底部输入栏尽量接近微信；但不提供假的“直接转发图片组”。无法调用微信聊天发送能力的地方明确使用“保存后回微信发送”。

### 3.3 预览不修改创作结果

左右滑动只改变当前预览中的顶层卡片，不修改编辑页的组内顺序，也不重新生成编号图。返回编辑页后，原项目、首图和保存顺序保持不变。

### 3.4 一次只解释当前动作

进入页面后只出现一次短暂手势提示；之后界面靠微信熟悉的手势和贴近牌堆的“展开 N”完成自解释，不持续堆叠教程。

## 4. 页面结构

从上到下分为四层：

1. **系统安全区**：使用真实系统状态栏，不渲染模拟时间；
2. **会话导航**：左侧返回，中间标题“好友”，右侧不再额外绘制省略号，避免与小程序原生胶囊冲突；
3. **聊天消息区**：微信浅色会话背景、消息时间、四个右侧图片消息组；
4. **预览输入栏**：保留微信输入栏外观但标记为“预览模式”，点击只提示保存后回微信发送。

四层中只有第 3 层是纵向滚动容器；第 1、2、4 层固定在当前一屏内。无论消息区滚到哪里，顶部会话导航、右上角原生胶囊和底部预览输入栏都不随消息移动。

### 4.1 导航

- 标题使用“好友”，表达用户正在查看朋友收到消息时的视角；
- 返回按钮回到原编辑/结果页，不丢失已经生成的编号图；
- 不硬编码另一套状态栏；
- 不在右侧再画“···”，直接保留系统小程序胶囊。

### 4.2 聊天背景与模式切换

- 模式名称采用微信现有口径“普通模式”和“深色模式”，界面不使用“白天色/夜晚色”作为正式名称；
- 颜色采用腾讯官方 WeUI 变量：普通模式聊天背景 `#EDEDED`、导航/工具栏 `#F7F7F7`、卡片 `#FFFFFF`；深色模式聊天背景 `#111111`、导航/工具栏 `#1E1E1E`、卡片 `#191919`；
- 会话导航右侧、原生小程序胶囊左边放置一颗太阳/月亮合并按钮。按钮是一个圆角分段胶囊，不是两个分离按钮；太阳和月亮始终可见，当前模式所在半区使用对应实底高亮；
- 点击整颗按钮在普通模式和深色模式之间切换，切换即时生效并保存到本地；首次进入没有历史选择时读取系统当前主题作为默认值；
- 控件对无障碍暴露“切换到深色模式”或“切换到普通模式”，不依赖颜色单独表达当前状态；
- 消息时间只出现一次，使用真实进入时间或“刚刚”，不再同时出现两套固定时间；
- 色值来源：[Tencent/weui-wxss 官方主题变量](https://github.com/Tencent/weui-wxss/blob/master/dist/style/base/variable/color.wxss) 与 [Tencent/weui DarkMode 用法](https://github.com/Tencent/weui/wiki)。

### 4.3 四个部位组

每个部位组是一条独立的“我发送的图片消息”：

```text
[展开 3]  [三层图片牌堆]  [我的头像]
```

- 整行右对齐；
- 头像固定 36px 方形、5px 圆角；
- 牌堆不再按固定 `54vw` 缩放，改为从“屏宽减去左右安全边距、头像、展开按钮和间距”后的消息通道计算可用宽度；
- 典型手机的正面图片卡宽度目标为 `min(38vw, 164px)`，最大视觉高度为 `min(51vw, 219px)`，最终仍受消息通道剩余宽度约束；
- 375px 宽设备上，1:1 趣味字画约为 143×143px；穿搭 4:5 输出与 3:4 输出在折叠态均使用约 143×191px 的紧凑 3:4 缩略框并居中填充，避免黑色空带；点击后由原生大图预览展示完整原图；
- 后两张只露出 6–12px 边缘，轻微缩放，不制造过大的空白卡；
- “展开 N”与牌堆保持 10–12px 间距并垂直居中，不再固定到屏幕最左侧；
- 展开胶囊改成浅灰半透明底、深色文字和轻阴影，按下时短暂变深；
- 组名不再悬浮在聊天流中；图片内容已经能表达部位，组名只保留在无障碍标签、长按菜单和保存结果里；
- 图片内 `01…N` 角标继续保留，它属于用户实际保存并发送的图片。

消息行高度由当前图片比例决定，不再固定为 164px。四组可以在中间聊天区自然纵向滚动，不为追求“一屏全放下”而把图片缩小到看不清；页面外壳本身不参与这次滚动。

### 4.4 固定视口与唯一滚动区

```text
系统状态区 / 小程序胶囊       系统固定
会话导航                       页面固定
────────────────────────────
聊天消息区                     唯一纵向滚动区
  时间
  图片消息组 1
  图片消息组 2
  图片消息组 3
  图片消息组 4
────────────────────────────
预览输入栏 / 底部安全区        页面固定
```

- 页面根节点锁定为设备实际可用视口高度并禁止外层滚动；不能仅依赖可能受安全区重复计算影响的普通 `100vh`；
- 会话导航和预览输入栏是固定高度的非收缩区域，中间消息区使用两者之间的剩余高度，并设置为唯一的 `scroll-view`；
- 消息区必须允许自身收缩，避免子内容高度把整个页面根节点撑开；
- iOS 回弹只发生在聊天消息区，不能带动导航栏或底部输入栏；
- 展开一组时只增加聊天消息区内部内容高度，并尽量保持触发按钮和当前首图的视觉锚点；
- 关闭大图后恢复原消息区滚动位置，页面外壳仍保持原位。

## 5. 核心交互状态

### 5.1 首次进入

- 页面立即显示已经生成的编号图；
- 第一叠旁边出现一次 2 秒提示：“左右滑动切换 · 点展开查看全部”；
- 用户首次滑动、展开或滚动后提示立即消失；
- 后续进入不重复强提示，可在本地记录已读状态。

### 5.2 折叠态左右滑动

- 左滑查看下一张，右滑查看上一张，循环切换；
- 横向位移超过卡宽 20%，或满足快速滑动速度阈值时翻页；
- 未达到阈值时自然回弹；
- 仅当前部位组改变，另外三组的顶层卡和展开状态保持不变；
- 首次方向判断为纵向时立即交还页面滚动，避免横纵手势抢夺；
- 识别为横向后，顶层图片严格跟手，后两张在牌堆舞台内按进度同步向前补位；消息行、头像、展开按钮、聊天区和页面外壳都不跟随横移；
- 松手完成切换时，顶卡以小角度移动约一张卡宽并淡出，后卡同时进入正面槽位；旧顶卡从另一侧回到尾层后只淡入露边，避免“整叠一起移动”或“飞走后突然换图”；
- 8px 后仍为接近 45° 的斜向手势时暂不抢占，只有横向意图明显才锁住聊天滚动；快速滑动也必须先产生至少 10px 位移；
- 滑动结束后不显示额外页码，图片内角标已经是顺序事实源。

### 5.3 展开

- 点击紧贴牌堆的“展开 N”，当前顶层图片保持原位；
- 折叠牌堆被替换为按“当前顶层 → 后续卡片”排列的连续右侧图片消息；展开态不再叠放，也不响应横向切图；
- 每张展开图片（包括第一张）都带各自的右侧头像，模拟同一用户连续发送图片；
- 新消息以 45ms 间隔轻微下移淡入，页面保持当前组首图可见；
- 展开后胶囊原位改为“收起”；收起完成后回到同一组附近，并恢复展开前的顶层牌面；
- 多个部位组允许独立展开，符合多个微信图片消息各自维护状态的模型；
- 收起后恢复为展开前的当前顶层卡，不跳回最初 `01`。

### 5.4 单张查看

- 折叠态单击顶层图片进入黑底大图；
- 展开态单击任意图片进入同一大图查看器；
- 左右滑动大图时只浏览当前部位组；
- 点击返回或下滑关闭后回到原滚动位置和原顶层卡；
- 图片加载失败时显示灰色占位与“重新加载”，不让整组消失。

### 5.5 长按

不模拟无法兑现的微信“转发”能力。

- 折叠牌堆长按：`保存这一组`、`取消`；
- 展开单张长按：`保存这张`、`保存这一组`、`取消`；
- 菜单标题显示实际组名，例如“上衣 · 3 张”；
- 保存过程显示“上衣 2/3”，失败后可从失败图片继续；
- 保存完成进入发送引导，不声称已经发给好友。

### 5.6 底部输入栏

- 输入框显示浅灰占位“预览模式”；
- 语音、表情、加号只保留轮廓，不提供点击反馈；
- 点击输入区域时显示轻提示：“这是效果预览，保存后回微信发送”；
- 输入栏固定在安全区上方，聊天消息滚动到底部时不会被遮挡。

## 6. 用户旅程

```text
编辑/结果页
  → 点击“微信预览”
  → 看到四条折叠图片消息
  → 左右滑动检查每个部位组的顺序与封面
  → 可选：展开某组，检查全部图片
  → 可选：单击查看大图、长按保存单张或当前组
  → 返回编辑/结果页
  → 点击“保存可用部位组”
  → 按组保存完成
  → 查看发送步骤
  → 用户自行回到目标微信聊天，按图片角标选择并发送
```

预览页的任务是回答“朋友会看到什么、怎么滑”，编辑/结果页的任务是回答“我要保存哪些组”。两个页面职责不混在一起。

## 7. 页面状态

| 状态 | 页面表现 | 用户动作 |
| --- | --- | --- |
| 准备中 | 右侧显示 1–2 条灰色牌堆骨架，标题下不闪烁错误 | 等待或返回 |
| 折叠可用 | 四组右侧牌堆，展开胶囊紧贴图片 | 滑动、展开、长按 |
| 纵向滚动 | 只有中间聊天消息区移动，导航与输入栏保持原位 | 继续查看下一组 |
| 横向滑动 | 只有当前顶层卡跟手移动，消息行和页面外壳保持原位 | 松手翻页/回弹 |
| 展开 | 当前组图片成为连续消息行 | 看大图、长按、收起 |
| 大图 | 黑底查看当前组，可左右浏览 | 返回/下滑关闭 |
| 保存中 | 原生 loading 显示组名与进度 | 等待 |
| 保存成功 | 底部结果面板说明已保存数量和下一步 | 继续预览/查看发送步骤 |
| 图片失败 | 单卡占位，不影响其他组 | 重新加载/返回 |
| 输入无效 | 不展示假聊天输入，只给一次说明 | 返回保存 |
| 空数据 | “没有可预览的图片”，主按钮“返回整理素材” | 返回 |

## 8. 发送完成引导

保存成功后使用真实产品面板，而不是伪装成微信消息：

1. 每次只选择一个部位组；
2. 按图片角标 `01…N` 勾选；
3. 发送前确认 `01` 在第一位；
4. 微信出现“发送后合并展示”时勾选后发送；
5. 再发送下一部位组。

按钮为“继续预览”和“我知道了”。不提供“一键打开指定聊天”或“一键转发图片组”。

## 9. 实现边界

- 继续复用 materialized manifest 和 `exportUrl`，预览不回退到未编号源图；
- 四组状态按 `stackId` 隔离；
- 滑动状态只保存在预览页内，不写回项目；
- 展开图片节点保持挂载，收起只切换可见状态，避免临时图重新解码白屏；
- 动画只使用 `transform` 和 `opacity`；
- 自定义导航高度从系统信息动态计算；
- 主题使用页面根节点 `theme-light / theme-dark` 状态类切换，不修改生成图片本身；用户选择写入本地存储，读取或写入失败时回退到普通模式，不影响预览主流程；
- 页面根节点使用实际视口高度并关闭外层溢出；会话导航和预览输入栏固定，中间 `scroll-view` 使用剩余高度且是唯一纵向滚动容器；
- 图片尺寸由独立布局函数根据视口、头像、展开按钮、边距和原图比例计算，删除 `54vw / 150px / 164px` 三个旧固定值；
- 手势先做横纵方向锁定：纵向交给消息区，横向只驱动当前牌堆顶层卡；
- `http://tmp`、`wxfile://` 等本地临时图继续遵循当前严格白名单；
- 不新增云端接口、AI 调用、账户或社交权限。

## 10. 验收标准

### 10.1 视觉

- 真机只出现一套系统时间和状态图标；
- 页面不再绘制与原生胶囊冲突的第二个右上角菜单；
- 聊天背景、导航、输入栏和消息排列分别接近微信普通/深色会话；
- 太阳/月亮显示在同一颗分段胶囊中，点击后普通模式与深色模式即时切换，重新进入仍保持选择；
- “展开 N”与对应牌堆距离不超过 12px，不再悬在屏幕左侧；
- 1:1 趣味字画保持方形；穿搭 4:5 和 3:4 在折叠态使用接近微信的 3:4 缩略框，卡内不出现上下空带，完整原图由大图预览承载；
- 四组折叠态均清楚可辨，纵向滚动无大片无意义留白；
- 首屏外壳始终占满设备可用视口，滚动消息时导航、系统胶囊和底部输入栏无位移；
- 不显示悬浮组名和假的可输入状态。

### 10.2 交互

- 四组可以分别左右循环滑动且互不重置；
- 纵向滚动只移动聊天消息区；横向滑动只移动当前牌堆的顶层图片，两者不冲突；
- 展开从当前顶层开始，收起后保持该顶层；
- 单张大图关闭后保持原滚动位置；
- 长按保存不出现误导性的图片“转发”；
- 返回编辑页后素材顺序、首图和生成结果不变。

### 10.3 兼容与验证

- 微信开发者工具、iOS 和 Android 分别验证安全区、胶囊避让、横纵手势和底部输入栏；
- 真实微信聊天对照验证封面、图片比例、展开/滑动结构和头像位置；
- 开发者工具模拟不替代真机结论；
- 图片失败、授权拒绝和保存中断均有可恢复路径。

## 11. 非目标

- 不在小程序里真正嵌入微信聊天；
- 不承诺不同微信版本像素级完全一致；
- 不调用或伪造直接发送给指定好友的能力；
- 不在本次加入聊天输入、评论或多人互动；
- 不改变图片内容、编号、保存顺序和叠图门槛。
