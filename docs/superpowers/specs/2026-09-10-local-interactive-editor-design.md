# 趣味字画本地交互与自由手写设计

日期：2026-09-10

状态：用户已确认书面设计；功能分支实施中，服务端011已部署。新客户端开关仍关闭，真实新接口/手绘审核导出与交互验收待完成，非已发布功能。

## 1. 目标和已有证据

在现有候选页和聚焦编辑页实现连续编辑，不让贴纸移动和手写笔迹等待服务器图片。继续使用现有 fun-card-renderer 的镜像内字体，不恢复客户端字体 CDN 为主路径。

已核对代码：编辑页 initProject 不接收候选图片缓存；syncProject 清空 fallbackImages/currentFallbackImage 并重置云端回退状态；onFontUnavailable 使用 buildPreviewPayload 请求整组候选；候选大框没有编辑点击绑定。当前涂鸦是预设程序化素材，不是手指采样笔迹。现有服务仅做文本审核，不能覆盖自由手绘内容。

用户观察的 3–5 秒没有分阶段测速，不能全部归因为冷启动或字体加载。

## 2. 本期范围

1. 候选大框点击进入编辑，按压反馈，保留左右滑动；打开当前可见卡片，防重复跳转。
2. 云端字体预览为主，缓存复用，更新不清空已显示图片，旧请求不能覆盖新编辑。
3. 程序化贴纸独立本地显示，拖动/缩放/旋转/改色不请求云端图片。
4. 自由手写：实线笔、半透明荧光笔，颜色、粗细、整笔擦除、撤销/重做和清空当前卡笔迹。
5. 本地可编辑草稿；最终图片仍走服务端可信调用和审核。

本期不包含：跨设备草稿同步、新账号体系、协作、用户照片导入、压感与倾斜保证、防手掌误触保证、真实毛笔纹理、手写识别、个人字体生成、任意无限图层。云端草稿同步是后续独立交付，不把云存储成图等同于草稿同步。

## 3. 渲染分工

采用云端文字底图 + 本地交互覆盖层。底图包含背景、背景纹理和文字，不包含可移动装饰和自由笔迹。程序化装饰仍使用现有白名单图形，不使用 emoji 替代真实素材。自由笔迹位于既有内容之上，首期不支持笔迹与文字交错层级。

为编辑增加明确的单卡底图预览接口，不伪造三张重复卡片满足旧接口数量规则。该接口只接受既有受限场景，执行现有可信身份与文本审核，再输出无交互装饰的底图。候选页使用同样底图叠加程序化装饰，以便进入编辑页直接复用；旧整图回退仍保留，但不能把含装饰的整图与同一套本地装饰同时显示造成重影。

最终 renderer 消费完整场景及受限笔迹数据，输出 1080 方图。前后端使用同一坐标空间和同值笔刷配方。普通贴纸变换和每一笔只改变本地数据，不触发底图请求。

## 4. 预览请求与缓存

缓存键由场景中底图相关字段与渲染协议版本确定，不使用数组下标作为身份。键不包含交互装饰和笔迹。缓存只在当前进程内按有界最近使用策略保留，URL失效或图片加载失败时失效重取。候选进入编辑传递缓存及 sceneId，不把 URL 写成永久素材。

文字、字体和背景修改合并约 400ms 后刷新当前底图；相同键合并请求，只接受最新场景版本的结果。更新期间保持上一次图片并明确标注“预览更新中”，失败则标记“预览未更新，重试”，不得伪装最新效果。没有任何可用底图时才显示初次加载状态；装饰/笔迹本地操作不被网络遮罩阻挡。

切换卡片、恢复、撤销、卸载必须使过期请求失效；图片存储路径使用版本隔离，避免并行请求覆盖同一个云文件。缓存不替代审核授权，最终输出仍独立校验。

## 5. 交互与笔迹模型

保留内容、样式、装饰三个一级入口。装饰内增加“贴纸 / 手写”二级切换。预览边缘提供明确“改文字”动作；非手写和非变换操作时点击文字预览打开编辑弹窗，不在笔迹触摸结束时误弹键盘。

手写模式单指绘制；整笔擦除按笔迹线段命中（包含单点笔迹和笔宽），删除整笔，不承诺像素擦除。触摸取消丢弃未提交笔迹，落笔锁住页面滚动，结束恢复。切卡、退出模式、打开键盘先结束或取消活动操作，避免把笔迹写入错误卡片。

使用 1080×1080 逻辑坐标，实际测量画布矩形后换算，不继续硬编码 320px 手势尺度。显示 Canvas 根据设备像素比例初始化；移动中的点保存在组件实例，不每点 setData 整组场景。绘制按帧合并，已完成内容缓存，避免每个触摸事件重画全部历史。

每笔记录 id、brushKey、colorKey、width、points；点记录有限数值 x/y，坐标限制在画布内。首期限制每卡 100 笔、每笔 1000 点、全卡 20000 点；达到限制提示并保留已有画面。采样简化保留起止点，单次点击绘制圆点。笔宽使用受限档位，不接收任意 Canvas 指令。荧光笔整笔合成透明度，避免触摸点重叠导致局部变黑。

每笔完成是一条撤销动作；一轮擦除手势是一条撤销动作；清空仅当前卡且需确认。复用现有20步历史，保存后的笔迹仍可继续编辑。项目模型版本兼容旧场景，缺失笔迹字段视为空；不得静默丢弃新数据。

## 6. 保存与安全

本地草稿包含场景和笔迹，不仅是 PNG；在落笔后合并写入已有本地项目存储。显示“已保存到本机”，不显示“已云同步”。保存失败明确提示；临时目录/微信清理和换设备无法保证恢复。已有最终卡片和导出 manifest 在任意编辑后失效，旧图片只可作编辑过渡，不能保存成最终结果。

服务端对笔迹结构、数量、坐标、颜色、笔宽及整体请求大小严格校验，继续保留身份、限流和文本审核。含自由笔迹的最终输出必须检查图像内容，只有明确通过才能返回可导出结果。异常、超时、审核未完成或审核能力未配置一律失败关闭，用户仍能保留本地草稿。

实施时先验证现有环境可用的图片审核接口及其授权，再接入真实实现。若需用户开权限或外部配置，立即报告具体缺项；不得用审核桩或文本审核结果冒充图像审核通过。未打通前不得将自由手写功能宣称为可发布或允许绕过审核导出。无需新增存储资源；若接口需要待审文件，只能复用已有存储并先核实访问边界，不能公开未审核文件。

## 7. 发布和回滚

当前服务010保持在线，开发先在功能分支验证。先部署兼容旧协议的服务器，再启用新客户端主路径；接口未就绪时明确提示而不是每笔降级重载。保留现有 CDN 配置和旧接口作兼容，不修改 CDN、VPC、子网、NAT、公网配置，不创建资源，不合并主分支或推送 GitHub。

新功能有显式开关；审核链路未验证时保持正式发布关闭。回滚界面时不删除本地笔迹项目，而是说明该版本暂不支持继续编辑。

## 8. 实施顺序与验收

1. 补缓存身份、过期响应、候选点击/滑动区分的失败测试，再实现这些逻辑。
2. 增加单卡底图接口与本地装饰覆盖层。测试拖动不新增网络请求、无重影、尺寸变换、更新不白屏。
3. 增加笔迹模型与纯绘制模块，先测边界、单点、擦除命中、撤销/重做、旧项目兼容，再接手写交互和本机草稿。
4. 扩展服务端受限笔迹绘制和图片审核门禁；拒绝、超时、缺配置不得输出最终文件。先做轻量真实审核能力检查，受阻立即报告。
5. 完成服务器兼容性测试、部署预检后再更新现有服务；真实调用验证字图、装饰与笔迹最终成图一致。
6. 运行项目治理检查，记录开发者工具和真机实际结果，不把自动化当作真机。重点连续画10笔、连续拖动、慢网、返回恢复和过期响应，不开展无关深度压力测试。

验收核心：笔迹和贴纸移动不产生渲染请求；有缓存进入编辑不重新等待整组；改字失败时画面保留且状态诚实；点击卡片可进入且滑动不跳转；最终图包含最新笔迹且通过真实审核。首次无缓存和最终生成不承诺秒开。
