# WePicTool 界面与页面模板基线

**版本：** Draft v1.0
**日期：** 2026-09-05
**状态：** 草案，等待用户确认；确认前不据此重构业务代码
**适用范围：** 微信小程序首页、输入页、候选页、编辑页、结果页、微信效果预览页、记录页和我的页

## 1. 设计目标

本基线把当前满意的首屏和主要页面沉淀为稳定框架。后续增加玩法或修改功能时，优先替换内容和业务插槽，不重新发明导航、页面层级、颜色、按钮、卡片、状态反馈和保存流程。

“固定模板”不等于把所有页面写死。应固定的是用户已经建立认知的外壳和组件契约；可变化的是玩法内容、素材、局部强调色和业务步骤。

## 2. 三层冻结策略

### 2.1 L1：产品外壳，默认冻结

- 底部导航固定为「首页 / 记录 / 我的」三 Tab；
- 首页固定为「任务选择 → 单一共享预览 → 当前玩法双行动 → 更多工具」四层；
- 创作链路固定为「输入/选素材 → 候选或整理 → 聚焦编辑 → 结果 → 微信效果预览 → 保存引导」；
- 微信效果预览是独立仿真壳层，不与普通产品页面混用；
- 所有页面只允许一个明确主行动；同级次行动使用次按钮，不新增第三种抢焦点按钮；
- 新玩法通过注册表接入，不直接在首页复制新的大型演示区或另建一套 Tab。

改变 L1 需要新的设计说明、用户确认、实施计划和回归范围。

### 2.2 L2：令牌与组件，受控冻结

- 颜色、字号、间距、圆角、阴影、按钮高度、页面边距只使用本文令牌；
- 同类组件的状态和点击区域保持一致；
- 允许扩充令牌，但必须先解释现有令牌为何无法表达；
- 不允许在新页面直接复制整段 WXSS 后只改颜色或文案。

改变 L2 可以是纯视觉修正，但必须截图对照并执行受影响页面回归。

### 2.3 L3：玩法内容，可迭代

- 玩法名称、说明、素材、候选内容、卡片数量和局部插画可变化；
- 穿搭叠图使用蓝紫强调，趣味字画可使用粉色强调；
- 玩法强调色只能进入图标、选中态、局部标签和内容画布，不能改变全局导航、页面背景或基础文本体系；
- 任何玩法变化仍需遵守 PRD、PLAYBOOK、统一导出和安全门禁。

## 3. 基础设计令牌

以下值来自当前已确认首页和微信预览方案。代码迁移时应落为统一变量或生成文件，页面不得继续新增近似重复值。

### 3.1 语义色

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `color-bg-page` | `#F7F8FC` | 普通产品页面背景 |
| `color-surface` | `#FFFFFF` | 卡片、输入框、底栏 |
| `color-text-primary` | `#151728` | 标题和主要正文 |
| `color-text-secondary` | `#8B90A6` | 说明、辅助信息 |
| `color-text-disabled` | `#999999` | 禁用和未上线状态 |
| `color-border` | `#ECECF0` | 普通分隔与边框 |
| `color-primary` | `#6670F6` | 全局主行动、选中态 |
| `gradient-primary` | `#8980FF → #6470F7` | 仅用于高优先级主按钮 |
| `color-fun-text` | `#ED65B5` | 趣味字画玩法强调 |
| `color-success` | `#07A350` | 成功与可用状态 |
| `color-warning-bg` | `#FFF9E6` | 风险或降级说明背景 |
| `color-danger` | `#E5484D` | 删除、失败和阻断 |

微信效果预览使用独立的仿真主题令牌：普通模式聊天背景 `#EDEDED`、导航/工具栏 `#F7F7F7`；深色模式聊天背景 `#111111`、导航/工具栏 `#1E1E1E`、图片承载面 `#191919`。这些颜色不得反向污染普通产品页面。

### 3.2 字体层级

| 令牌 | 建议值 | 用途 |
| --- | --- | --- |
| `type-display` | `40rpx / 1.25 / 700` | 首页核心问题或空状态标题 |
| `type-title` | `32rpx / 1.35 / 700` | 页面和主卡标题 |
| `type-section` | `28rpx / 1.4 / 600` | 分区标题 |
| `type-body` | `26rpx / 1.55 / 400` | 主要正文与按钮 |
| `type-meta` | `24rpx / 1.5 / 400` | 次级说明 |
| `type-caption` | `22rpx / 1.4 / 400` | 状态、角标、辅助标签 |
| `type-micro` | `20rpx / 1.35 / 500` | 极短徽标，不用于长正文 |

普通界面统一使用系统中文无衬线字体栈；授权手写字体只用于趣味字画生成内容，不用于导航、按钮或正文。

### 3.3 间距、圆角和阴影

- 间距刻度：`8 / 12 / 16 / 24 / 32 / 40 / 48rpx`；页面水平边距固定 `24rpx`；
- 圆角：小控件 `12rpx`，输入/缩略图 `16rpx`，普通卡片 `20rpx`，主面板 `24rpx`，胶囊 `999rpx`；
- 不再新增 `22/26/28/30/32/34rpx` 等近似卡片圆角；历史页面迁移时归并到最近的标准值；
- 普通卡片阴影：`0 2rpx 8rpx rgba(57, 63, 101, .05)`；
- 浮层阴影：`0 12rpx 28rpx rgba(57, 63, 101, .12)`；
- 边框优先于强阴影，单个首屏不超过一个高强调渐变面。

### 3.4 尺寸与安全区

- 触控目标最小 `88rpx × 88rpx`；
- 主按钮内容高度不低于 `88rpx`；
- 页面底部操作区必须包含 `env(safe-area-inset-bottom)`；
- 自定义导航必须使用系统状态栏和小程序胶囊数据计算，不硬编码模拟状态栏；
- 页面布局至少验证 375×667、390×844 和一台常见 Android 高屏；横屏不是当前目标。

## 4. 页面骨架模板

### T1：首页发现模板

```text
页面标题/任务问题
两张等宽玩法选择卡
唯一共享主预览
主行动 + 次行动
更多工具（紧凑入口）
原生底部 Tab
```

规则：共享预览一次只解释一个玩法；切换玩法保留各自进度；未上线工具必须标记状态；首页不放完整教程、重复入口或无内容装饰卡。用于说明可滑性的空闲动画一次只能改变一个局部，用户触摸后立即暂停，页面隐藏或切换玩法时停止。

### T2：输入/素材整理模板

```text
原生导航
简短目标说明
核心输入或分组素材区
必要的轻量选项
校验/降级提示
底部固定主行动
```

适用：`pages/fun-text`、`pages/dressup`、`pages/outfit-import`。业务内容可变，导航、边距、状态反馈和底部行动结构固定。

穿搭工作台的“自己分层 / AI 帮我整理”必须表现为同一任务的两种添加方式，而不是两个互斥模式 Tab：用户可反复混用且已有素材保持不变。AI 子流程先选图、再处理、后复核，只有确认时回填；不确定项以可见待确认区承接，不能静默误分或覆盖。

### T3：候选选择模板

```text
原生导航
候选标题与简短差异说明
真实可操作预览
候选切换或三套列表
“使用这套”主行动
“自己改改/再来一组”次行动
```

适用：`pages/fun-text-candidates` 和未来多方案玩法。候选差异必须来自策略或内容，不得只是换色。

### T4：聚焦编辑模板

```text
原生导航
当前卡/当前组预览
不超过 3 个一级编辑入口
顺序与封面提示
底部“完成/生成结果”主行动
```

编辑器不得暴露无限图层或专业画布参数。新增编辑能力优先进入二级面板，不能持续挤压主预览。

### T5：结果与导出模板

```text
结果摘要
实际 exportUrl 预览
生成/物化进度与可恢复错误
“微信预览”次行动
“按叠保存”主行动
保存后的统一发送引导
```

规则：预览和保存必须消费同一 materialized manifest；每叠从 `01` 开始；失败显示具体叠和序号；不能承诺系统相册自动排序或直接发送到聊天。

### T6：微信效果预览模板

该模板独立于普通产品页面：系统区与胶囊只出现一次，会话导航和底部预览栏固定，中间聊天消息区是唯一纵向滚动区；横向手势只控制当前顶层图片。详细规格以 `../superpowers/specs/2026-09-05-wechat-preview-simulation-redesign.md` 为准。

### T7：记录/设置列表模板

```text
原生导航
分区标题或筛选
白色列表/记录卡
空状态或危险操作说明
原生底部 Tab
```

记录项必须显示玩法类型、时间和可恢复状态；不可恢复的历史数据给升级说明，不伪装可继续编辑。

## 5. 标准组件清单

| 组件 | 稳定契约 | 允许变化 |
| --- | --- | --- |
| `PageShell` | 页面背景、水平边距、安全区 | 是否有底部固定操作 |
| `PlaySelector` | 两列、选中边框、勾选、无障碍状态 | 图标、标题、玩法强调色 |
| `SharedPreviewPanel` | 单一主预览位置、稳定高度、加载/失败态 | 玩法实际内容 |
| `PrimaryAction` | 主色/渐变、88rpx 最小高度、禁用与加载态 | 文案、图标 |
| `SecondaryAction` | 白底、主色边框、与主按钮同尺寸 | 文案 |
| `SectionHeader` | 28rpx 标题、可选右侧状态 | 标题和状态文字 |
| `SurfaceCard` | 白底、20/24rpx 圆角、标准边框/阴影 | 内部插槽 |
| `StatusNotice` | info/success/warning/error 四种语义 | 具体文案和恢复按钮 |
| `BottomActionBar` | 固定底部、安全区、主次行动顺序 | 单按钮或双按钮 |
| `StackPreview` | manifest、独立 stack 状态、等比图片 | 单叠/多叠、主题 |
| `SendGuide` | 五步真实发送口径 | 实际叠名称 |

第一轮迁移不必立即创建自定义组件；可以先把令牌和 class 契约集中，确认无视觉变化后再按复用次数提取组件。

## 6. 业务与视觉的边界

页面不得直接决定以下业务事实：玩法是否可用、每叠最少张数、顺序、封面、导出 URL、安全审核结果和发布开关。它们分别来自玩法注册表、项目模型、manifest、安全客户端和环境配置。

业务模块不得硬编码以下视觉事实：全局主色、页面背景、标题字号、卡片圆角、按钮高度、状态色和安全区。它们来自设计令牌或共享 class。

这样，新功能只需声明“我是什么玩法、输入什么、生成什么、使用哪种强调色”，不再复制完整页面框架。

## 7. 新页面准入清单

新增或重做页面前必须回答：

1. 它属于 T1–T7 中哪个模板；若都不属于，为什么需要新模板？
2. 主行动是什么，是否只有一个？
3. 是否复用玩法注册、共享预览、manifest、保存、记录和安全能力？
4. 是否只使用已定义令牌？
5. 加载、空、失败、禁用、部分成功和恢复状态是否齐全？
6. 375×667、390×844、Android 高屏和底部安全区是否验证？
7. 是否新增了会改变用户认知的导航、颜色或组件？若是，是否先完成设计确认？

## 8. 建议迁移顺序（确认后再写实施计划）

1. 盘点现有 WXSS，把重复值映射为语义令牌，不改变视觉；
2. 先统一 `PageShell`、按钮、卡片、分区标题和状态提示；
3. 将首页作为 T1 基准页，建立截图与结构回归；
4. 按 `dressup → fun-text → candidates → editor → result/template-result → record/profile` 迁移；
5. 微信预览按 T6 独立维护，不强行套普通页面主题；
6. 加入设计令牌静态检查，阻止新页面继续新增未经登记的颜色、圆角和字号；
7. 双端真机确认无视觉回归后，再删除旧重复样式。

## 9. 验收标准

- 新增玩法不修改三 Tab、首页四层结构或结果保存主链路即可接入；
- 普通页面不再出现未登记的主色、卡片圆角和字号；
- 同一主/次按钮在所有页面的高度、圆角、加载和禁用状态一致；
- 首页、输入、候选、编辑、结果、预览、记录七类页面都有明确模板归属；
- 设计系统迁移前后，已确认页面在目标设备尺寸上无有意视觉变化；
- `npm test`、语法、小程序预检、类型和文档治理全部通过；
- iOS/Android 真机记录安全区、键盘、长列表、加载、失败和返回恢复结果。

## 10. 待用户确认的冻结结论

建议一次确认以下四项：

1. 三 Tab 和首页四层信息架构作为 L1 长期基线；
2. 蓝紫作为全局主色、粉色只作为趣味字画玩法强调色；
3. T1–T7 作为后续页面模板，新页面必须选择其一；
4. 先做“无视觉变化”的令牌与共享组件迁移，再新增照片玩法。

确认后再新建逐文件实施计划；确认前本文只作为审阅稿，不修改现有页面行为。
