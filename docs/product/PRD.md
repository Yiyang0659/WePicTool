## 1. 产品定位

### 1.1 一句话定位

> 微信「合并发送 / 叠图」玩法生成器：把图片、素材或一句话变成有封面、有顺序、有节奏的一叠图，让用户在发送前预演，按叠保存后回微信发送。

### 1.2 第一性价值

产品处理的是微信发送前的素材准备，不替代微信发送。微信擅长把用户已经选好的图片传给好友并展示合并叠图，但不会替用户完成分类、去背、统一画布、按部位分组、确定封面与顺序、预演效果或设计互动玩法。

因此产品只有在“发送前还需要整理或设计”时成立：

| 用户当前状态 | 更合适的选择 | 原因 |
| --- | --- | --- |
| 只有几张已经整理好、顺序明确的图片 | 直接使用微信 | 不额外增加步骤 |
| 图片杂乱、背景不统一、不清楚如何分组 | AI 穿搭整理 | 把原始照片自动变成可发送素材组 |
| 已有按部位素材，想让好友参与组合选择 | 分层换装 | 把素材组织成四叠可独立滑动的互动玩法 |
| 想让一句话具有滑动节奏和揭晓感 | 趣味字画 | 把文字转成适合合并发送的叙事卡片 |

产品的核心产出不是“多看一次图片”，而是把未经准备的内容变成更省事、更有序、更容易理解也更好玩的微信发送包。

### 1.3 产品形态

- 微信小程序，展示名「滑一叠」，仓库名 WePicTool；
- 无需账号即可使用本地能力；
- 用户内容默认只用于当前处理和本地记录；需要云端处理时执行内容安全与临时存储规则；
- 小程序不直接把图片发送给指定好友，只负责生成、预演、保存和真实发送引导。

### 1.4 核心用户任务

用户不是为了使用一套复杂图片工具，而是为了更快完成微信里的社交表达：

1. “我想把几件衣服整理好，让朋友滑着帮我选。”
2. “我想把头像、上衣、下装和鞋分别做成四叠，让朋友像玩纸娃娃一样组合。”
3. “我想把一句普通的话变成有停顿和落点的滑卡。”
4. “我想把一组内容发得有序、不刷屏，而且对方看得懂怎么滑。”

### 1.5 产品原则

- 先完成社交任务，再暴露工具能力；
- 每个玩法都必须走统一的输入、生成、预览、导出、发送和记录管线；
- 模板和手动路径先成立，AI 只做增强，失败不能阻断可用主链路；
- 轻编辑优先，不做通用画布；
- 预览和保存使用同一最终导出图；
- 对微信能力保持诚实，不承诺直接发送或系统相册自动排序。

## 2. 目标用户

| 用户 | 典型场景 | 需要的结果 |
| --- | --- | --- |
| 穿搭求建议用户 | 买衣服、出门前搭配、网购下单前 | 干净、分组、有编号的可对比图片 |
| 好友/情侣表达用户 | 想念、感谢、道歉、玩梗或轻反转 | 有悬念、节奏和末尾落点的文字滑卡 |
| 微信高频分享用户 | 多图分享、聚会、日常内容 | 有封面、有顺序、不刷屏的一叠图 |
| 个人创作者/卖家 | 商品或素材需要快速整理 | 统一画布、主体清楚、可批量保存的图片 |

首个发布版本不以专业创作者、商家团队或复杂协作作为目标。

## 3. 产品信息架构

### 3.1 全局导航

底部三 Tab 固定为：

- 首页：选择任务、理解玩法并开始；
- 记录：查看本地任务、恢复可继续项目；
- 我的：权限、缓存、反馈、隐私和版本说明。

新玩法不得增加顶级 Tab。只有产品主任务发生根本变化时，才允许通过独立设计确认调整导航。

### 3.2 首页

首页固定为四层：

1. “今天想做什么？”任务问题；
2. 分层换装 / 趣味字画两张主玩法选择卡；
3. 单一共享主预览与当前玩法的主/次行动；
4. 紧凑的更多工具。

穿搭 AI 整理是当前可用的次级工具，不再与两种主玩法竞争首屏。未实现的玩法必须明确标记“即将上线”，不能做成看似可点击的假能力。

分层换装的首页共享预览中，头像/发型、上衣、下装、鞋子各自只显示一张可辨认的当前图片；用户通过原生横向手势或左右箭头循环切换，右侧按四部位顺序竖向汇总当前选择。图片不得定时自动变化。

### 3.3 当前能力层级

| 层级 | 能力 | 产品角色 |
| --- | --- | --- |
| 主玩法 A | 分层云换装 | 当前旗舰：四叠独立滑动和自由组合 |
| 主玩法 B | 趣味字画 | 当前文字玩法：一句话生成三套有节奏滑卡 |
| 次级工具 | AI 穿搭整理 | 真实衣物分类、去背和白底整理 |
| 共享底座 | 微信效果预览、manifest、可见序号、保存、记录、安全 | 所有玩法必须复用 |
| 后续玩法 | 照片、节奏、故事、群聊互动 | 通过路线图逐步接入，不先占首页主叙事 |

分层换装与 AI 穿搭整理的边界固定如下：分层换装是“用户决定分类，工具负责组织成可互动四叠”，强调控制感、搭配选择和好友参与；AI 穿搭整理是“用户一次交给工具一批杂乱照片，工具负责分类与标准化”，强调减少分类、去背和统一画布的重复劳动。前者不是 AI 整理的结果页，后者也不替代四部位玩法。

## 4. 不可变产品规则

1. 每个希望形成微信合并展示的叠至少 3 张；不足时只能说明普通发送、补素材或跳过。
2. 不用空白卡、教程卡或无关封面卡为分层换装硬凑 3 张。
3. 每叠第一张是预期封面，最终图片内显示 `01…N` 可见序号。
4. `wx.saveImageToPhotosAlbum` 不能指定相册目标文件名或排序；产品只能串行保存并指导用户按角标确认 `01` 在第一位。
5. “保存全部”“保存可用叠”都不等于“一键发送”；发送必须由用户回到微信完成。
6. 图片或文字需要云端处理时先过内容安全；审核异常默认不放行。
7. AI 分类、抠图或故事规划失败时，已有手动/规则路径继续可用；不能用未经审核内容绕过失败关闭。
8. 结果页和微信效果预览必须消费同一 materialized manifest 和 `exportUrl`，不能预览一种图、保存另一种图。
9. 用户编辑后旧 manifest、旧保存断点和过期异步结果必须失效。
10. 不加产品水印；编号属于功能性顺序标识，不是品牌水印。

## 5. 核心用户旅程

### 5.1 分层云换装

```text
首页选择分层换装
→ 手势或箭头调整四个部位并在右侧确认当前组合
→ 直接试玩 / 上传自己的素材
→ 头像、上衣、下装、鞋子四组整理
→ 删除、排序、系统素材补齐
→ 四叠微信效果预览
→ 保存达到门槛的部位组
→ 回微信按组发送
```

手动按组上传必须能够独立完成，AI 分类或去背不是前置条件。

### 5.2 趣味字画

```text
首页选择趣味字画
→ 用示例试玩 / 从 12 个案例取灵感 / 输入一句话
→ 选择表达感觉（可跳过）
→ 得到三套真实可滑候选
→ 直接使用 / 在内容、样式、装饰中局部调整
→ 生成最终图片并预演
→ 按序保存
→ 回微信发送
```

P2.1 使用规则策略保证完整闭环；P2.2 AI 只允许生成结构化故事计划，不直接生成最终中文图片。

### 5.3 AI 穿搭整理

```text
首页更多工具选择 AI 穿搭整理
→ 先进入空选图状态
→ 主动添加 1–9 张图片，可追加、单张删除或清空重选
→ 选择输出比例
→ 压缩、上传、安全审核
→ AI 分类与可选去背
→ 上衣/下装/鞋子/其他分组
→ 改分类和结果检查
→ 物化编号图并预演
→ 按组保存并回微信发送
```

## 7. 非功能需求

### 7.1 性能

| 场景 | 目标 |
| --- | --- |
| 1 张穿搭图端到端 | ≤ 10 秒（待真实模型复测） |
| 3 张穿搭图端到端 | ≤ 20 秒（待真实模型复测） |
| 9 张穿搭图端到端 | ≤ 60 秒并持续显示真实进度 |
| 分层换装直接试玩 | 不触发网络或 AI，首屏素材可立即交互 |
| 趣味字画规则候选 | 输入审核后尽快展示可滑低清候选；最终高清只渲染所选方案 |
| 主包体积 | 上线预检硬性小于微信 2 MiB 限制，1.8 MiB 起预警 |

### 7.2 可靠性

- 单张失败不阻断其他成功结果；
- 所有异步生成使用 generation 隔离，旧结果不得覆盖新编辑；
- 批量保存显示当前叠和序号，可从失败处继续；
- 本地草稿和历史记录必须有版本校验，不安全或损坏记录不得恢复进生成链路；
- 云端不可用时，只有文档允许的本地路径可以降级，安全错误不得绕过。

### 7.3 隐私与安全

- 不建立账号、云端历史同步或长期用户画像；
- 用户上传和生成文件按 24–72 小时策略清理；趣味字画 `funtext/` 目标固定 48 小时；
- 客户端不得包含 AppSecret、模型密钥或伪造 OpenID/context；
- 云托管头部检查不能替代平台公网关闭；
- 用户输入和模型新增文字在生成前/渲染前按设计执行审核，异常默认不放行。

### 7.4 兼容与可访问性

- 支持 iOS/Android 主流微信版本；
- 安全区、系统胶囊、键盘、长列表和相册权限必须真机验证；
- 选择状态不只依靠颜色表达；按钮、主题切换和错误恢复提供清晰文字；
- 图片保持原比例，不拉伸；预览失败时显示占位与重试，不让整组消失。

## 8. 成功指标

当前阶段先验证可用性，不以功能数量为目标：

| 指标 | 定义 | 首轮目标 |
| --- | --- | --- |
| 示例理解率 | 进入首页后能通过试玩理解叠图用途 | 定性测试多数无需额外解释 |
| 创作完成率 | 从选择玩法到得到可保存 manifest | ≥ 85%（内测样本） |
| 按叠保存率 | 完成创作后至少保存一叠 | ≥ 50% |
| 发送引导完成率 | 保存后查看并完成发送步骤 | ≥ 25% |
| 穿搭白底可用率 | 内测认为值得保存的白底结果 | ≥ 70% |
| 趣味字画候选差异通过率 | 三套结构、落点和视觉不只是换色 | 人工评审 ≥ 80% |
| 次日复用 | 第二天再次打开并开始创作 | 先观察趋势，不设付费目标 |

当前尚无统一事件上报模块，上述指标在埋点完成前只能通过人工内测记录，不能声称已有线上数据。

## 9. 当前不做

- 通用图片编辑器、无限图层、专业调色、蒙版和滤镜；
- 模板商城、付费、账号、社区和云端历史同步；
- AI 直接生成带最终中文文字的图片；
- 真实 AI 试穿、人体重建或对真人身体的推断；
- 恐怖惊吓、羞辱、冒充真实聊天或造成实际误导的整蛊；
- 小程序直接发送多图到指定聊天；
- 依靠文件名控制系统相册或微信图片选择器顺序；
- 未经许可的品牌、明星、游戏角色或第三方作者素材。
